# Research And Vault Workflows

Use these rules for Carrel tasks that are not simple ingestion or setup.

## Vault Notes

- Create notes inside `notes/`, `_meta/`, or a domain-specific folder under the
  vault root.
- Use templates from `assets/templates/` when a note type matches.
- Prefer links and stable filenames over moving files opportunistically.
- Use the safe-write runtime helpers for generated artifacts.

## Research Partner Work

The agent owns intellectual synthesis. Do not force all research thinking
through scripts. Use scripts only to persist completed reflections, mirrors, or
handoff documents.

## Knowledge Wiki

Use a `wiki/` folder only after the researcher opts in or the task clearly asks
for a compounding knowledge base. Keep source notes separate from synthesized
wiki pages. Preserve researcher callouts and corrections.

## Self-Improvement

When a recurring custom solution emerges, add it as a template, reference, or
script only after it is useful beyond one session. Record the durable behavior
in the skill pack rather than in host-specific commands.

## Model Teammates

Treat multi-model teammates as host adapters. Record durable preferences in the
profile or context file, but do not require any one host's plugin ecosystem for
portable Carrel behavior.

Use cases that belong in portable Carrel:

- second-pass literature synthesis;
- adversarial review of claims or coding decisions;
- long-context pass over a source bundle;
- collaborator-facing clarity review.

Before sending material to another model, apply the same sensitivity and cloud
consent gates as any other adapter. Keep install commands and provider-specific
routing outside the portable workflow.
