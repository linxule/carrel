# Migration: 0.5.1 → 0.5.2

## What's New

- **Setup is now resumable.** `/carrel-setup` writes `.carrel/setup-state.json` to track progress (`last_completed_phase`, `completed_at`, `version`). The session-start hook detects paused setups and surfaces a one-line resume prompt:
  - "Setup paused after the vault was scaffolded. Run /carrel-setup to resume from here."
- **Two natural pause points.** The setup explicitly offers to pause after Phase 4 (vault scaffolded, profile written) and after Phase 7 (cheat sheet & verification). Researchers can stop and pick up later without re-interviewing.
- **Honest time framing in the interviewer opening.** The setup-interviewer now states up front: "About 15-20 minutes of conversation with me, plus 10-15 minutes of human steps. We can pause anytime."
- **`carrel vault cheatsheet` CLI subcommand.** Backs the existing `/carrel-cheatsheet` command. Reads `.carrel/environment.json` via Pydantic, regenerates `_meta/cheat_sheet.md`. Replaces the deleted `generate-cheatsheet.js`.
- **Legacy Node scripts removed.** `skills/environment-setup/scripts/{check-environment,create-vault,generate-cheatsheet}.js` were superseded by the Python CLI in v0.3 but still referenced by docs. They had drifted to write invalid Pydantic data (e.g., `sensitivity='prefer_local'` not in the enum). All references now point to the canonical Python CLI commands.

## What Changed

- New file written by `carrel vault init`: `.carrel/setup-state.json`
  ```json
  {
    "last_completed_phase": 4,
    "version": "0.5.2",
    "completed_at": null
  }
  ```
- New CLI: `carrel vault cheatsheet [--vault PATH] [--force] [--format human|json|quiet]`
- Deleted: `skills/environment-setup/scripts/` (entire directory)
- `commands/carrel-setup.md` — added Time Expectations + State Tracking sections; pause prompts after Phase 4 and Phase 7; phase markers for skippable phases; resume protocol
- `commands/carrel-cheatsheet.md` — uses `carrel vault cheatsheet --force`
- `skills/environment-setup/SKILL.md` — Mode Detection now handles paused setup; Step 8 uses the new CLI; legacy script section replaced with Tooling section pointing to the canonical Python CLI
- `agents/setup-interviewer.md` — opening now sets honest time expectations and mentions pause points
- `hooks/check-environment.js` — reads `.carrel/setup-state.json` and surfaces a one-line resume prompt for paused setups
- `src/carrel/vault/scaffold.py` — writes `.carrel/setup-state.json` after `environment.json`

## Why Now

- **Schema correctness**: the legacy .js scripts were a latent ticking bomb. They wrote `sensitivity='prefer_local'` (invalid Pydantic) and hardcoded `version='0.1.0'`. Any researcher who hit them via the SKILL/command docs would have produced unparseable config. Spec 006 will add a validator layer to catch this class of bug systematically; v0.5.2 closes the immediate hole.
- **Faculty deployment readiness**: a 30-45 min one-shot setup is too much commitment for time-pressed researchers. Pause-and-resume removes the all-or-nothing feeling.

## Automatic Migrations

These run silently with no user action:

1. **Update plugin-state.json**: Version bumped to 0.5.2.
2. **Existing vaults without `setup-state.json`**: the file is written by `carrel vault init`, which only runs during fresh setup. Existing vaults DO NOT get a `setup-state.json` retroactively. The hook treats its absence as "setup probably complete" (no resume prompt). To add it manually: write `{"last_completed_phase": 9, "version": "0.5.2", "completed_at": "<today>"}` to `.carrel/setup-state.json`.

## Manual Steps

None required. To explicitly mark an existing vault as "setup complete" so the hook never offers resume even if logic later changes, drop this file:

```bash
echo '{"last_completed_phase": 9, "version": "0.5.2", "completed_at": "'$(date -u +%Y-%m-%d)'"}' > .carrel/setup-state.json
```

## No Action Required If

- You're a returning user with a working vault — nothing changes for you.
- You don't use `/carrel-cheatsheet` — the CLI replacement is transparent.
