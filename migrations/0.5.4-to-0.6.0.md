# Migration: 0.5.4 → 0.6.0

**Milestone**: Markdown control plane closure.

## What's New

v0.6.0 ships spec 008 (trust enforcement) as a full code boundary, resolves the two upstream-research blockers on spec 007 (cross-platform support is now implementation-ready), and closes the `.carrel/exports/` privacy hangover. 143 tests pass (up from 105 in v0.5.4 — trust policy, trust CLI, google cleanup, and the existing suite).

### Spec 008: Trust Enforcement Code Boundary (the headline)

The second "markdown control plane" closure, following the setup-state CLI pattern from v0.5.3. Trust levels were previously documentation contracts Claude was asked to honor; now there's a Python gate.

**New CLI surface — `carrel trust`:**
- `carrel trust check <action> --vault PATH` — exits 0 if the action is allowed at the current trust level, exits with `CarrelError` otherwise. The error message names the action, current trust, and minimum required trust, with a hint pointing to `/carrel-automate`.
- `carrel trust list --vault PATH` — prints all 7 gated actions with allowed/denied status at current trust.
- `carrel trust show --vault PATH` — prints current trust level.

**Action vocabulary (hierarchical namespace:verb form):**
| Action | Description | Required Trust |
|--------|-------------|----------------|
| `automation:propose` | Write a proposal to `_meta/pending-approvals.md` | Consultative |
| `automation:execute` | Execute a previously approved automation step | Delegated |
| `automation:write-prompt` | Write/update `_meta/automation-prompt.md` | Delegated |
| `wiki:propose` | Suggest enabling the knowledge wiki | Consultative |
| `wiki:write` | Create/update wiki pages autonomously | Delegated |
| `vault:move-file` | Move a file from `inbox/` to a typed folder | Delegated |
| `vault:reorganize` | Move/rename files outside inbox routing | Partnership |

**Skill integration**: 7 gated write sites (`skills/automation/SKILL.md`, `skills/knowledge-wiki/SKILL.md`, `skills/knowledge-wiki/references/trust-activation.md`, `commands/carrel-automate.md`) now instruct Claude to run `carrel trust check <action>` before the write. If check fails, Claude surfaces the gate to the researcher and stops.

**Design decisions (locked pre-implementation)**:
- Hierarchical action vocabulary, not per-action enums
- No `--force` backdoor — override path is trust elevation via `/carrel-automate`
- Audit log deferred to v2 (spec 011 hook integration can surface drift later)
- Writes-only scope; read-side trust gating is out of scope

**Promoted**: `AutomationConfig.trust_level` from string `Literal` to proper `TrustLevel(str, Enum)` in `models.py`. Backward-compatible (string values preserved in JSON serialization via `str` mixin).

### `.carrel/exports/` Privacy Cleanup

`carrel google export` now deletes the raw exported file (`.docx`, `.pdf`) from `.carrel/exports/` after successful conversion to markdown. Prevents silent accumulation of sensitive Google Doc duplicates that researchers think they only have as markdown.

New flag: `--keep-export` opts out (for debugging or when the raw file is genuinely wanted). Cleanup is skipped on conversion failure (raw file needed for debugging the failure). Closes Codex §5 finding from the 009 audit.

### Spec 007 Unblocked

Both upstream-research lock blockers resolved via direct verification against recent upstream releases:

- **Liteparse** supports Windows via `bun add -g @llamaindex/liteparse` (matches Carrel's existing coli/defuddle pattern). Tesseract.js bundled; no system dependencies for PDF parsing. PyPI v1.2.1 also provides a universal wheel.
- **gws** shipped first-class Windows support in v0.22.5 (2026-03-31). Install via `npm install -g @googleworkspace/cli`. One-time OAuth setup workaround documented (Rust binary `.cmd` resolution quirk).

Spec 007 updated (`planning/specs/007-cross-platform-support.md`): Lock Blockers section now reads "RESOLVED 2026-04-20"; tool matrix shows cross-platform install paths; Web Clipper dropped from recommendations (not a fit for the Docs editor canvas); Google Docs native Markdown export added as a tip. Implementation-ready; schedule for 0.7.0.

Research artifact: `planning/research/007-windows-tools-research.md` with full source citations.

## Why Now

The 009 holistic audit (April 2026) identified the "markdown control plane" as the load-bearing architectural risk for long-term Imperial deployment: trust, sensitivity, and profile-sync flows lived as prose contracts rather than code boundaries. Sensitivity and path containment were stopgapped in v0.5.4 (B4 + A4). Spec 008 closes the trust dimension properly.

The spec 007 unblock came from a research pass that found upstream had shipped Windows support for both blocker tools in March-April 2026, faster than the spec assumed.

## Automatic Migrations

These run silently with no user action:

1. **Update plugin-state.json**: Version bumped to 0.6.0.
2. **Existing vaults**: no schema changes to `environment.json`. `TrustLevel` enum's `str` mixin preserves existing string values on JSON read/write. The trust check is additive — no existing skill is forced to call it unless the updated SKILL markdown is loaded.
3. **Existing `.carrel/exports/` files**: NOT auto-deleted. The cleanup only affects files created by v0.6.0+ `carrel google export` calls. Manually clean old exports with `rm -rf .carrel/exports/*` if desired.

## Manual Steps

None required for working vaults. Optional hygiene:

```bash
# See what your current trust level unlocks
carrel trust list --vault .

# Check a specific action before running it
carrel trust check automation:propose --vault .

# Clean up any lingering raw exports from before v0.6.0
rm -rf .carrel/exports/*
```

## Breaking Changes

Technically none — backward-compatible at the data layer. But behavioral changes worth noting:

1. **Skills that previously wrote to `_meta/pending-approvals.md` or similar at Advisory trust**: those writes now trigger a trust check that will reject. If a skill session relies on this (shouldn't — the skill contract said Advisory = no writes), it will now fail loudly instead of silently succeeding. This is the whole point; flagged for visibility.
2. **`carrel google export` default behavior**: raw files in `.carrel/exports/` are now deleted on success. Add `--keep-export` to the CLI call if you want the pre-v0.6.0 behavior.

## No Action Required If

- You're a returning user with a working vault at `trust_level=advisory` — you never triggered the gated writes anyway; nothing changes.
- You don't use Google Workspace export — the exports cleanup is additive and doesn't affect you.
- You don't actively run `/carrel-automate` or `/carrel-research` — the trust check only fires on those flows.
