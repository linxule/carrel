# Migration: 0.6.0 → 0.7.0

**Milestone**: First-class cross-platform support + final markdown control plane closure.

## What's New

v0.7.0 ships **four specs in a single release** — the largest single migration in Carrel's history. 228 tests pass (up from 143 in v0.6.0 — 85 new tests across the four specs).

- **Spec 007** — Cross-platform Windows + Linux (Imperial PC researchers now first-class)
- **Spec 010** — Policy module (sensitivity routing with 16-row decision matrix + `--explain`)
- **Spec 011** — Profile sync architecture (regenerators + drift check via HTML-comment markers)
- **Spec 006** — Environment validation and self-healing (validator + auto-fix + doctor agent)

Together these close the last architectural gaps flagged in the 009 holistic audit.

## Spec 007: Cross-Platform Support

Carrel now works natively on macOS, Linux, and Windows. No WSL required. All Tier 1 tools install cross-platform.

**New module**: `src/carrel/env/platform.py`
- `Platform` enum (MACOS / LINUX / WINDOWS / UNKNOWN)
- `detect_platform()` from `sys.platform`
- `AuditResult.platform` field populated by `carrel env doctor`
- `PlatformToolMatrix` model for per-tool per-platform availability

**install.py refactor**: per-tool dicts keyed by `Platform`. Tools standardized on `bun add -g` or `npm install -g` for cross-platform packages:
- liteparse: `bun add -g @llamaindex/liteparse` (all platforms; replaces Homebrew tap)
- gws: `npm install -g @googleworkspace/cli` (all platforms; replaces Homebrew)
- obsidian: `brew --cask` / `winget install` / AppImage
- ffmpeg, bun, zotero: platform-branched appropriately

**audit.py**: Obsidian/Zotero detection is now platform-aware (was `mdfind`-only before). Windows probes `%LOCALAPPDATA%\Obsidian` / `%PROGRAMFILES%\Zotero`. Linux checks `~/.config/obsidian`, `~/.zotero`, plus `shutil.which`.

**Cheatsheet renderer** takes a `platform` parameter and emits OS-correct install commands. `_meta/cheat_sheet.md` for a Windows researcher shows `winget install ...` where a macOS cheatsheet shows `brew install ...`.

**Decision tree & SKILL files** rewritten with OS-aware install tables. `/carrel-setup` Phase 2 extracts `audit.platform` and uses it for every subsequent install recommendation.

**gws Windows OAuth workaround** documented in `references/gws-setup-guide.md` (Rust binary `.cmd` resolution quirk; manual OAuth Desktop credential creation).

**install.ps1** reaches parity with install.sh (verification step; bun install; same Tier 1 tool checks).

## Spec 010: Policy Module (Sensitivity Routing)

Sensitivity routing is no longer a consent.py stopgap — it's a deterministic 16-row decision matrix at `src/carrel/policy/sensitivity.py`.

**Matrix summary** (see spec 010 for the full table):
- **HIGH**: refuses cloud tools regardless of consent or explicit `--tool` override. `gws` included (Google API calls leave the machine).
- **MEDIUM**: requires explicit `--tool <cloud>` to route to cloud; `cloud_consent=True` alone is insufficient.
- **LOW**: local-first; `cloud_consent=True` auto-routes when local tool unavailable; explicit `--tool <cloud>` always counts as consent.

**`--explain` flag** on `carrel paper convert`, `carrel transcript create`, `carrel google export`:

```bash
$ carrel paper convert sensitive.pdf --explain --tool mineru
Decision: refused
Rationale: HIGH sensitivity — blocked cloud tool (mineru) regardless of consent
```

Prints the routing decision + rationale without executing. Essential for debugging pilot-deployment routing surprises.

**Namespace**: `src/carrel/trust.py` moved to `src/carrel/policy/trust.py`. A one-line backward-compat shim at the old path preserves existing imports; will be removed in v0.8.0.

**Backward compat**: `consent.py:resolve_cloud_consent` kept as a thin wrapper around `policy.sensitivity.select_tool`. All existing tests pass unchanged.

## Spec 011: Profile Sync Architecture

Profile data no longer drifts silently across 5 surfaces. Four new CLI sub-commands close the gap:

- **`carrel vault dashboard --vault . --force`** — regenerates `_meta/my-environment.md` (living dashboard: trust, sensitivity, configured tools, activity stats from file counts)
- **`carrel vault automation-prompt --vault . --force`** — regenerates `_meta/automation-prompt.md` from `AutomationConfig` (deterministic, replaces prose Claude was asked to hand-write)
- **`carrel vault check-sync --vault .`** — reads HTML-comment markers in vault CLAUDE.md, compares to `environment.json`, prints drift table, exit non-zero on drift
- **`carrel vault add-markers --vault .`** — one-time migration for pre-v0.7.0 vaults; appends marker pairs

**Marker schema** (inserted by `carrel vault init` and writable/readable by `vault/markers.py`):
```html
<!-- carrel:sensitivity -->medium<!-- /carrel:sensitivity -->
<!-- carrel:cloud_consent -->false<!-- /carrel:cloud_consent -->
<!-- carrel:trust_level -->consultative<!-- /carrel:trust_level -->
<!-- carrel:tools_configured -->liteparse,coli,defuddle<!-- /carrel:tools_configured -->
<!-- carrel:wiki_enabled -->false<!-- /carrel:wiki_enabled -->
```

Obsidian renders HTML comments invisibly. Explicit, machine-parseable, future-proof.

**Hook integration**: `hooks/check-environment.js` runs `carrel vault check-sync` once per 24 hours (stamped via `last_checked_at` in plugin-state.json). Surfaces a one-line banner on drift: "⚠ Profile drift detected in CLAUDE.md — run `carrel vault check-sync` for details."

**Scaffold.py**: fresh vaults get markers populated from the interview profile automatically.

## Spec 006: Environment Validation and Self-Healing

Three-layer architecture for catching and fixing configuration drift:

### Layer 1: `carrel env validate --vault PATH`

Deterministic read-only validator. Reports:
- Pydantic parse errors (field-level paths)
- Drift warnings: extra keys, deprecated values, version mismatch, `tools_configured` vs actual `tool_matrix` mismatch, CLAUDE.md marker / environment.json desync

Exit codes: `0` valid, `1` invalid, `2` drift-warnings-only.

### Layer 2: `carrel env fix --safe --vault PATH`

Conservative auto-healer. Known-safe fixes:
- Sensitivity rename (`'prefer_local'`/`'cautious'` → `'medium'`; `'external'` → `'low'`)
- Version bump to current plugin version
- Missing optional fields → sensible defaults
- `tools_configured` boolean re-sync via `PlatformToolMatrix` (spec 007 integration — the most valuable cross-spec win)
- Orphaned unknown keys → preserved in `_unknown_keys` sub-field

Writes `.carrel/environment.json.bak` before any change. `--dry-run` shows fixes without applying. Refuses ambiguous cases.

### Layer 3: `/carrel-fix` + `skills/env-doctor/`

Interactive resolution for ambiguous drift. Plain-language Qs: "Your CLAUDE.md says sensitivity: HIGH but environment.json says LOW — which is right?" Logs every applied change to `_meta/capability-log.md` with revert instructions.

**Hook integration**: once-per-24h drift surfacing (same cadence as check-sync). Banner: "⚠ Environment drift detected — run `/carrel-fix` for details."

## Why Now

The 009 holistic audit (April 2026) named the "markdown control plane" as the load-bearing architectural risk. v0.5.3 closed setup-state. v0.5.4 stopgapped sensitivity (HIGH only). v0.6.0 closed trust enforcement. **v0.7.0 closes the remaining dimensions: full sensitivity routing (010), profile sync (011), and environment validation (006) — while simultaneously making Carrel cross-platform (007)**.

Imperial College Business School deployment is now truly unblocked. Mac users and Windows users get parity.

## Automatic Migrations

These run silently with no user action:

1. **Update plugin-state.json**: Version bumped to 0.7.0; new `last_checked_at` field for hook drift cadence.
2. **Existing vaults**: no schema changes to `environment.json`. The new `_unknown_keys` field (introduced by spec 006 Layer 2) is optional. Existing `tools_configured` values are preserved until a researcher runs `carrel env fix --safe` which will sync them against actual installs.
3. **`trust.py` import compat**: `src.carrel.trust` still works (thin shim); prefer `src.carrel.policy.trust` for new code.

## Manual Steps for Existing Vaults (Optional)

```bash
# Add HTML-comment markers to your vault CLAUDE.md for drift checking
carrel vault add-markers --vault .

# Verify your profile is in sync across all surfaces
carrel env validate --vault .

# Apply any safe fixes the validator surfaces
carrel env fix --dry-run --vault .     # preview
carrel env fix --safe --vault .        # apply

# Regenerate deterministic surfaces
carrel vault dashboard --vault . --force
carrel vault automation-prompt --vault . --force
```

## Breaking Changes

Behavioral (not data layer):

1. **`/carrel-setup` Phase 4 now writes HTML-comment markers into the scaffolded CLAUDE.md**. Previously absent. Existing vaults without markers get a hint from `carrel vault check-sync` to run `add-markers`.
2. **Routing decisions for MEDIUM-sensitivity profiles** now follow the 010 matrix strictly. If researchers had a workflow that relied on `cloud_consent=True` auto-routing at MEDIUM (which was unclear behavior before), they now need to explicitly `--tool <cloud>`. This is the whole point — removes ambiguity.
3. **`carrel google export` auto-cleanup** (v0.6.0 behavior) is preserved; mentioned here for continuity.

## No Action Required If

- You're on macOS and don't run `/carrel-setup` again — you can opt into the sync features when ready.
- You don't use cloud tools (mineru, groq, gemini, gws) — routing changes don't affect you.
- You're already at the latest trust level you want — spec 008's gate from v0.6.0 is additive.
