# Migration: 0.5.0 → 0.5.1

## What's New

- **`/carrel-share` — collaborator handbook generator.** A new command that synthesizes your accumulated vault context (friction log, capability log, reflections, configured tools, sensitivity rules, active threads, wiki conventions) into a markdown handbook tailored to a specific collaborator. Output: `_meta/handbook/[YYYY-MM-DD]-for-[name].md`, optionally also saved as `_meta/lab-handbook.md`. Vault-specific, not Carrel-general — distinct from `/carrel-setup` (which is for new researchers setting up their own vault).
- **New `collaborator-onboarding` skill.** Defines the synthesis logic and section template behind `/carrel-share`. Can also be invoked when a researcher mentions sharing the vault, onboarding a teammate, or generating a lab handbook — even without typing the command.
- **Onboarding now asks about Claude Code familiarity and collaborators.** Two short questions added to the setup interview:
  - "Have you used Claude Code before, or is this your first time?" → recorded as `claude_code_familiarity: "new" | "some" | "experienced"`.
  - "Do you work with co-authors, RAs, or a lab — anyone who might want to use this same setup?" → recorded as `collaborators: bool` plus an optional free-text `team_context` (e.g., "lab of 4 PhDs", "co-author at Cornell").
- **`/carrel-setup` Phase 9 surfaces next steps based on the new fields:**
  - If you're new to Claude Code → `/powerup` (if available in your install) for a guided tour of the assistant itself.
  - If you have collaborators → `/carrel-share` to generate a vault-specific handbook when you're ready to bring someone in.
- **Vault `CLAUDE.md` records the Claude Code context** so Claude can suggest these commands organically mid-session.

## What Changed

- `ResearcherProfile` gains three optional fields (backward compatible — all default to `None`):
  - `claude_code_familiarity: Literal["new", "some", "experienced"] | None`
  - `collaborators: bool | None`
  - `team_context: str | None`
- New files:
  - `commands/carrel-share.md`
  - `skills/collaborator-onboarding/SKILL.md`
  - `skills/collaborator-onboarding/references/handbook-template.md`
- `agents/setup-interviewer.md` — Middle conversation flow extended with the two new screening questions.
- `commands/carrel-setup.md` — Phase 9 (Handoff) offers `/powerup` (softened) and `/carrel-share` conditionally based on the new profile fields.
- `skills/environment-setup/SKILL.md` — Step 1 lists the new fields, Step 5 documents a new "Claude Code Context" section in the personalized vault `CLAUDE.md`.
- `skills/environment-setup/references/interview-protocol.md` — adds an "About Their Collaborators" section and the three new fields to the JSON output schema.
- `CLAUDE.md` (project root) — `/carrel-share` added to the Commands line in the Scheduled Automation section.

## Why `/carrel-share` and Not `/team-onboarding`

Claude Code ships a `/team-onboarding` command that analyzes local Claude Code usage to generate a generic teammate ramp-up guide. We considered referencing it directly, but `/team-onboarding` produces tool-usage tips — it doesn't know about Carrel conventions, your vault structure, your wiki schema, your sensitivity rules, or your active analytical threads. `/carrel-share` reads the vault directly and produces a vault-specific handbook. They serve different needs:

| Command | What it produces |
|---------|------------------|
| `/carrel-setup` | Working Carrel environment for someone new |
| `/carrel-share` | Vault-specific handbook for a collaborator joining an existing vault |
| `/team-onboarding` (Claude Code built-in) | Generic Claude Code usage tips from your local session history |

If you want all three for different audiences, run them all. They don't conflict.

## Why `/powerup` Is Softened

`/powerup` shipped in Claude Code v2.1.90 (April 1, 2026) alongside the `/buddy` April Fools' command. Whether `/powerup` is permanent isn't fully documented. We surface it conditionally and qualify the recommendation ("if available in your install") so the message ages well either way.

## Automatic Migrations

These run silently with no user action:

1. **Update plugin-state.json**: Version bumped to 0.5.1.
2. **ResearcherProfile compatibility**: Existing `environment.json` requires no changes — all new fields default to `None` and Pydantic v2 ignores their absence.

## Manual Steps

None required. If you want to backfill the new fields on an existing vault:

1. Open `.carrel/environment.json` and add (optional) `"claude_code_familiarity"`, `"collaborators"`, `"team_context"` at the top level.
2. Or just say "update my profile — I'm [new/experienced] with Claude Code and I [do/don't] work with collaborators" and Claude will edit both `environment.json` and the vault `CLAUDE.md` to match.
3. To try the new command on an existing vault: run `/carrel-share` and answer a few questions about your collaborator. The handbook will appear at `_meta/handbook/`.

## No Action Required If

- You don't have collaborators and don't need a handbook — `/carrel-share` is opt-in.
- Your existing commands, automation, and wiki work unchanged.
