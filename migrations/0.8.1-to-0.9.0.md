# 0.8.1 → 0.9.0

Minor release. **Architecture normalization + CC plugin feature adds** (spec 014, re-scoped to Claude Code only). Slash commands keep working; the orchestration moves to skills, and the deterministic ops move to the Python CLI. Three new CC plugin features ship alongside.

Originally drafted as a cross-CLI port for Codex CLI + Kimi CLI; re-scoped to CC-only after triage. The multi-host port is parked as future work — see `planning/specs/014-cc-plugin-v090.md` "Future work" section.

## What's new

### A. Architecture normalization

- **7 new CLI subcommands** extract deterministic file I/O from slash commands into typed Python CLI:
  - `carrel vault feedback export --redact-list <path>` — anonymized friction-log/capability-log digest
  - `carrel migrate apply --plugin-root <path>` (defaults to `$CLAUDE_PLUGIN_ROOT`) — registry walk + plugin-state.json write
  - `carrel vault mirror --write --from-stdin` — idempotent dated mirror file
  - `carrel vault reflect-log --append --from-stdin` — atomic append to dated reflect-log
  - `carrel vault share generate --mode --for --sensitivity` — collaborator handbook synthesis with sensitivity-based redaction (now supports `--explain` dry-run)
  - `carrel batch convert <folder>` / `carrel batch transcribe <folder>` (both: `--unattended`) — folder walker dispatching to existing converter/transcriber
  - `carrel automate configure --enabled --trust-level --schedule --review-cadence` — typed flags only, no prompting; gated internally via `policy.trust.is_allowed("automation:propose")`

- **3 enriched skills** absorb the orchestration prose freed from the corresponding slash commands:
  - `automation` — full 10-step interview flow + Desktop App walkthrough + unattended-batch contract
  - `convert` + `transcribe` — pre-batch confirmation, document-type routing report, post-batch summary
  - `collaborator-onboarding` — three sensitivity tiers + interactive vs quick mode
  - Plus three fill-in absorptions (the UNIQUE 4 prose homes): `self-improve` (migrate orchestration), `research-partner` (mirror 5-dimension synthesis), `session-reflection` (new skill — reflect + feedback)

- **7 wrappers shrunk** (`/carrel-{feedback,migrate,mirror,reflect,share,batch,automate}`) to thin `!carrel <subcmd> ${ARGS}` shell-calls (single line, no conditionals, no embedded prose). Total body lines: 564 → 35.

- **`${ARGS}` vs `$ARGUMENTS` convention** documented in `commands/CONVENTIONS.md`:
  - `${ARGS}` — skill-constructed (typed-flag arg list built by the calling skill)
  - `$ARGUMENTS` — raw user input (reserved for commands whose contract IS direct user input)

- **`tests/test_command_wrappers.py`** — structural validation: every shrunk wrapper matches the template; every command file has valid frontmatter.

### B. CC plugin feature adds

- **Marketplace metadata expansion** in `.claude-plugin/marketplace.json`: `keywords`, `category`, `tags`, `license` (MIT), `repository`. Visible on next `claude plugin marketplace refresh`.

- **`UserPromptSubmit` hook** (`hooks/inject-context.js`): injects a 3-5 line vault context summary (sensitivity, cloud consent, trust level, active brief) into every turn, not just SessionStart. Reads `.carrel/environment.json` + most-recent `_meta/briefs/` file. Silent no-op outside carrel vaults. 2s timeout.

- **`PreToolUse` Bash matcher** (`hooks/sensitivity-gate.js`): when a `carrel ... --tool (mineru|groq|gemini)` invocation is about to fire, the hook calls `carrel <subcmd> ... --explain` to learn the routing decision, then returns `permissionDecision: "deny"` (if sensitivity blocks) or `"ask"` (MEDIUM/HIGH allowed) before the subprocess runs. Pure UX layer — the `policy.sensitivity` module remains the authoritative enforcement at the CLI boundary. Bypass via `# bypass-gate` comment in the command. 3s timeout.

### New skill

- **`skills/session-reflection/`** — handles session-reflection check-ins (writes to `_meta/reflections/`, friction log updates) and feedback-digest export (read/write symmetry — reads what it writes). New skill defended because no existing skill matched the meta-research-tool conversation shape.

## What changed

- **Slash command surface preserved** — `/carrel-feedback`, `/carrel-migrate`, `/carrel-mirror`, `/carrel-reflect`, `/carrel-share`, `/carrel-batch`, `/carrel-automate` still work. They now delegate to skills + CLI rather than carrying the orchestration in their own body.
- **Orchestration prose rehomed** into skills. Migration file lists which prose lives where now (see "Prose rehome" below).
- **`hooks/hooks.json`** gained `UserPromptSubmit` and `PreToolUse` blocks. Existing `SessionStart` + `SessionEnd` hooks unchanged.
- **`AutomationConfig` schema unchanged** — the new `carrel automate configure` CLI uses the existing `AutomationSchedule` enum (`daily|weekdays|weekly`) and existing `review_cadence` literal (`monthly|quarterly|biannual`), even though spec text loosely described "cron-expr" and "weekly|monthly." Backward compat preserved over literal spec wording.

None — additive throughout. Existing vaults keep working. Marketplace metadata refreshes on next `claude plugin marketplace refresh`.

## Manual steps (optional)

- New `UserPromptSubmit` hook fires on every turn. If it causes any latency you notice (>100ms per turn), report it — the hook should be near-invisible.
- New `PreToolUse` Bash matcher will prompt for confirmation when you run `carrel <subcmd> ... --tool <cloud-tool>` from inside a CC session. Append `# bypass-gate` to the command to skip the confirmation for that one invocation. The gate also passes through silently if the command contains shell control characters (`;`, `&`, `|`, `<`, `>`, `` ` ``, `$`) — use `# bypass-gate` for those cases.
- If you maintain forks or external skills referencing the old slash-command bodies (e.g., quoting `/carrel-automate`'s 10-step flow), the prose now lives in `skills/automation/SKILL.md`. Same for the other six rehomes — see below.

## How the 7 shrunk commands work now (important)

The shrunk wrappers are designed to be invoked through skills, not as standalone shell calls. When you type `/carrel-mirror` (or any of the other 6), Claude reads the matching skill (`research-partner` for mirror, `self-improve` for migrate, `session-reflection` for reflect/feedback, `automation` for automate, `convert`/`transcribe` for batch, `collaborator-onboarding` for share) and constructs the typed-flag arg list before the wrapper fires.

- **Skill-driven (normal path)**: `/carrel-mirror` → skill activates from description triggers → Claude produces the synthesis → wrapper fires with `--write --from-stdin` and the synthesis piped in.
- **Direct shell (works for some, errors for others)**: typing the wrapper with no args (e.g., `/carrel-mirror` followed by Enter and nothing else) will pass empty `${ARGS}` to the CLI. Subcommands that require flags (`vault mirror`, `vault reflect-log`, `vault feedback export`) will error with an actionable message. Subcommands with sensible defaults (`migrate apply`, `vault share generate --mode quick`) will run.
- **Raw CLI**: every new subcommand is also available outside CC as `carrel <subcmd> --help`. The skill-driven path is the ergonomic one; the raw CLI is the audit/automation path.

## Debugging hooks

If the new `UserPromptSubmit` or `PreToolUse` hooks misbehave (no context appears, sensitivity gate doesn't fire), set `CARREL_HOOK_DEBUG=1` in your shell environment. Both new hook scripts emit `[carrel:<hook-name>] <reason>` lines to stderr on every silent-fail path. The existing `check-environment.js` and `session-reflect.js` use stderr unconditionally.

## Design notes

Scope was triaged twice during planning:
1. Original spec 014 ran 4 reviews (Codex, Kimi, code-architect, then self-trim) targeting a multi-host plugin builder. Round 1 surfaced 18+ amendments.
2. Re-scope to CC-only (2026-05-17) ran a third triage that cut 9 of 24 Phase 1 deliverables (cross-CLI motivated only) and added 3 CC features the original spec missed.

Net effort: ~1 large unit (from ~2 in the cross-CLI version). The architecture wins still hold — the three-layer rule (*skills = judgment, CLI = ops, transports = thin*) is now enforced for the 7 highest-value command paths.

Cross-CLI port (Codex + Kimi) remains parked as future work — see `planning/specs/014-cc-plugin-v090.md` "Future work" section. All Round 1 investigations and reviews remain authoritative if/when the port resumes.
