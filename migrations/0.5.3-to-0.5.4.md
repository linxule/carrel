# Migration: 0.5.3 → 0.5.4

## What's New

Holistic audit pass (`planning/reviews/009-holistic-audit-triangulated.md`) closed two pilot blockers, hardened security boundaries, and removed a thick layer of dead code. 105 tests pass (up from 62 in v0.5.3 — A4, A5, H4, H5, H8, H9, H17, H19 added focused coverage).

### Pilot blockers closed

- **`render_cheat_sheet` no longer ships a broken `/carrel-research` slash command.** Wiki-enabled cheat sheets now contain natural-language wiki guidance instead. (B1)
- **`hooks/session-reflect.js` now handles flat `ResearcherProfile` shape.** Previously dead for every vault scaffolded post-v0.4 — silently exited before the reflection prompt, vault stats, and capability log nudges. Now mirrors the flat-or-nested fallback from `check-environment.js`. (B2)
- **`read_profile()` raises `CarrelError` instead of `pydantic.ValidationError` / `json.JSONDecodeError`.** A corrupted or stale `.carrel/environment.json` no longer produces a Python traceback in `paper convert`, `transcript create`, `google export`, or `env profile` — researchers see actionable guidance ("Run /carrel-setup to regenerate it"). The v0.5.3 A7 fix only patched `vault cheatsheet`; this is the systemic fix. (B3)

### Security boundaries

- **Sensitivity HIGH blocks cloud routing.** `consent.py` now returns `False` from `resolve_cloud_consent` whenever `sensitivity == Sensitivity.HIGH`, regardless of `cloud_consent`. Closes the gap where the README promised "local-first when sensitive" but the routers ignored sensitivity. This is the deployment-time stopgap; full policy module is deferred to spec 010. (B4)
- **Path containment for vault writes.** New `src/carrel/safe_path.py` provides `safe_vault_join(vault, *parts)` that resolves the joined path, asserts it sits under the vault root, and raises `CarrelError` otherwise. Used by all filers (`convert/filer.py`, `transcribe/filer.py`, `vault/scaffold.py`, `google/export.py`). Symlinked subdirs that point outside the vault are now rejected. (A4)
- **`carrel vault new <name>` slug validation.** Names containing `/`, `\`, `..`, or only special characters are rejected. Previously a typo could produce unexpected directories or escape the intended note folder. (A4)

### Cross-platform propagation

- **Skill files now match `commands/carrel-setup.md` cross-platform guidance.** `decision-tree.md`, `environment-setup/SKILL.md`, and `obsidian-setup.md` were still recommending `brew install obsidian` (also: bare `obsidian` was wrong even on macOS — Obsidian is a cask). Windows and Linux researchers reading the SKILL flow now see correct guidance. (B5)

### Schema correctness

- **`AutomationConfig.last_reviewed` and `ResearcherProfile.wiki_proposal_deferred_until`** now enforce `pattern=r"^\d{4}-\d{2}-\d{2}$"` (matching the `SetupState` treatment from v0.5.3). Hand-edited dates like "yesterday" or "2026-13-99" are rejected at the model boundary instead of producing `Invalid Date` NaN comparisons in the hook. (A5)

### Behavioral improvements

- **Transcript idempotency across day boundaries.** `transcribe/filer.py` no longer embeds today's date in the destination filename, so re-running the same audio at 23:59 vs 00:01 correctly hits the SHA hash check. The transcription date moves to the markdown frontmatter where it belongs. (H1)
- **`carrel transcript create --speakers N` now reaches `coli`.** Previously declared and immediately discarded. (H2)
- **`gws` adapter raises `ConversionError` (not `ToolNotInstalled`) on auth failure.** Prevents the misleading "reinstall gws" hint when the actual fix is `gws auth login -s drive`. (H3)
- **Cloud HTTP adapters (mineru, groq, gemini) now guard `response.json()`.** Non-JSON 200 OK responses (rate-limit HTML, captive portals, proxy interstitials) raise `ConversionError`/`TranscriptionError` with actionable hint instead of `json.JSONDecodeError`. (H4)
- **`youtube_captions` uses typed exceptions** (`TranscriptsDisabled`, `NoTranscriptFound`, `VideoUnavailable`) with specific hints per failure mode. (H5)
- **`vault status --format quiet` prints the vault path.** Previously printed nothing. (H6)
- **Migration nag-spam debouncer.** The session-start "Carrel updated: X → Y" prompt is now shown at most once per 24 hours via `last_acknowledged_version` + `last_acknowledged_at` in `.carrel/plugin-state.json`. The `version` field standardized to `plugin_version` (the canonical name documented in CLAUDE.md). (H7)
- **`cloud_consent` rendered as text in hook banner** (`'cloud OK'` / `'prefer local'`) instead of raw `true`/`false`. (H8)
- **`gws` is now treated as a cloud tool** for consent purposes (Google API call — data leaves the machine). Subject to the same B4 sensitivity gate. (H9)
- **`_transcribe` unreachable error uses correct tool name.** GROQ now also gets the longer 300s timeout (it processes the same audio files via network). (H10)

### Refactor / dedup

- **Single YouTube URL parser** at `src/carrel/youtube_url.py` replaces three implementations across `transcribe/router.py`, `vault/organize.py`, `transcribe/adapters/youtube_captions.py`. Handles `/embed/`, `/shorts/`, `/live/`, query-param, and `youtu.be/` forms uniformly. (H11)
- **Single source-hash helper** at `src/carrel/source_hash.py` replaces twin `_source_hash` helpers in `convert/filer.py` and `transcribe/filer.py`. (H12)
- **`skills/vault-ops/templates/` removed.** Stale duplicate of root `templates/`; only the root is loaded by `vault/templates.py`. (H13)
- **12 empty `catch {}` blocks in `check-environment.js` replaced with `console.error` logging** (`carrel-hook: <context>: <error>`). Failures are now diagnosable in production. (H14)
- **Pure pass-through wrappers in `cli/paper.py` and `cli/transcript.py` removed.** Direct calls to underlying pipeline functions; `_for_file` aliases gone. (H15)
- **Triple re-export of `resolve_cloud_consent`/`resolve_vault` in `cli/main.py` removed.** Canonical re-export remains in `cli/__init__.py`. (H16)
- **`env/install.py` dead doctest scaffolding converted to real tests** at `tests/test_install.py`, covering `obsidian`/`ffmpeg`/`bun` on `darwin`/`win32`/`linux`. (H17)
- **`install.ps1` step 1 renamed "System prerequisites"** with curl check (matching install.sh). `bootstrap.sh` now prints a runtime deprecation banner. (H18)

### Dead code removal (parametric ghosts)

- **`ConvertOptions` and `TranscribeOptions` deleted** from `models.py` (vestigial DTOs from spec 001; zero importers). (A6)
- **`update_profile` deleted** from `env/profile.py` (zero importers). (A6)
- `sensitivity` and `hardware` parameters on routers retained — `sensitivity` is now consumed by the consent gate (B4), and the eventual A2 policy module work will use both.

### Documentation coherence

- **`skills/environment-setup/references/cheatsheet-template.md` rewritten** as a faithful description of what `render_cheat_sheet` actually emits. The previous Mustache/Handlebars template was fictional. (A7)
- **`skills/environment-setup/references/hardware-audit.md` rewritten** with the actual `AuditResult` Pydantic shape. The previous nested `{system: {...}, tools: {...}, existing_mcps: {...}}` schema didn't match the current flat model. (A8)
- **Tier 2 documentation batch (S1-S12)**: bootstrap.sh framing → install.sh canonical; AutomationConfig per-capability booleans shown in interview-protocol; self-setup-guide cross-platform Obsidian; vault-ops vault diagram includes `_meta/local/` + `_meta/reflections/`; setup-interviewer notes AutomationConfig truncation; Phase/Step numbering note in environment-setup SKILL; carrel-migrate doc writes `plugin_version`; SKILL.md clarifies which legacy scripts were removed; carrel-share `--quick` reframed as a behavioral mode; toolchain-guide stale `data_types` reference removed.

### Test coverage

- **6 previously-untested CLI commands** now have smoke coverage: `vault new` (including path-traversal rejection), `vault search`, `vault status` (including quiet format), `vault organize`, `paper list`, `transcript list`. (H19)

## Why Now

The deployment-readiness sprint (008) and the v0.5.3 release closed the immediate Imperial pilot blockers. The 009 holistic audit asked: "what would an experienced engineer joining today push back on?" — and surfaced a different class of risk: error contracts leaking past CLI guards, dead code masquerading as load-bearing, doc drift in skill files Claude actually loads, and policy boundaries that exist as prose contracts but not code.

This release closes the items the audit could fix in code without spec work. Three deferred items (A1 trust enforcement code guard, A2 full policy module, A3 profile-sync architecture) remain — they are spec-worthy and tracked separately.

## Automatic Migrations

These run silently with no user action:

1. **Update plugin-state.json**: Version bumped to 0.5.4. The new `plugin_version` (canonical) and `last_acknowledged_version` / `last_acknowledged_at` fields are written by the hook on first read.
2. **Existing vaults**: no schema changes to `environment.json` or `setup-state.json`. New date validators on `AutomationConfig.last_reviewed` and `wiki_proposal_deferred_until` are forward-only — existing values that don't match the pattern will fail validation if the file is re-read; in practice the only writers are Claude (who follows the documented schema) and `carrel setup-state` / `vault init` (deterministic).

## Manual Steps

None required for working vaults. Optional hygiene:

```bash
# Verify no malformed dates in your environment.json (will surface a CarrelError if so)
carrel env profile --vault .

# Verify your sensitivity gate works as expected
carrel env doctor --vault .
```

## No Action Required If

- You're a returning user with a working vault — nothing changes for you except quieter session-start banners and no Python tracebacks on stale config.
- You don't use the cheat sheet — the renderer changes are additive (fewer broken refs).
- You don't run on Windows — the cross-platform skill propagation is additive.
- You haven't enabled cloud tools (mineru/groq/gemini/gws) — the sensitivity gate and consent enum changes don't affect you.
