# Migration: 0.5.2 → 0.5.3

## What's New

- **`carrel setup-state` CLI.** Deterministic surface for setup-state transitions. Replaces the prior pattern of Claude editing `.carrel/setup-state.json` by hand.
  - `carrel setup-state advance --phase N --vault PATH` — atomically moves to the next phase. Rejects regressions; rejects out-of-range phases.
  - `carrel setup-state complete --vault PATH` — sets `last_completed_phase=9` and `completed_at=<today>`. Idempotent.
  - `carrel setup-state show --vault PATH` — pretty-prints current state.
  - `carrel setup-state reset --vault PATH --confirm` — recovery; logs to capability log when present.
- **Tightened `SetupState` Pydantic model.** `last_completed_phase ∈ [4, 9]`; `version` validated against semver; `completed_at` validated against `YYYY-MM-DD`. New mutual-implication invariant: `last_completed_phase == 9 ⟺ completed_at is not None`. Catches the "phase 9 with null completed_at" middle state at the model boundary instead of silently falling through SKILL.md mode detection.
- **Hardened `check-environment` hook.** Validates `setup-state.json` shape before using it: integer phase in `[4, 9]`, sensible `completed_at`. Malformed file produces a one-line diagnostic instead of silent skip. Resume logic now also covers `phase==9 && completed_at==null`.
- **`install.ps1` verification step.** Mirrors `install.sh` Step 8 — `Get-Command` checks for git, node, bun, uv, gh, claude, surfaces missing tools and a PATH-refresh hint. Bun fallback URL fixed (`irm https://bun.sh/install.ps1 | iex`).
- **`carrel env doctor` checks for bun.** Closes the gap where bun was installed but never probed.
- **Cross-platform `/carrel-setup` guidance.** Stopgap for Imperial deployment ahead of full spec 007. Phase 6 now offers OS-branched Obsidian install (`brew` / `winget` / AppImage). Decision tree opens with a platform note. Helper `install_command_for(tool, platform)` added in `env/install.py`.
- **README clarity on Windows readiness.** Platform Support matrix near top of README. Install script status separated from per-tool status; downstream gaps (liteparse, gws) explicitly named instead of hidden behind "handles everything else".
- **`carrel vault cheatsheet` beefed up.** New sections in `_meta/cheat_sheet.md`: configured tools (with example commands per tool), common workflows (driven by `preferences.*` flags), next steps. Aligned with Phase 7 framing of cheat sheet as the core handoff artifact.
- **`carrel vault` raises actionable errors on corrupted `environment.json`.** `ResearcherProfile.model_validate_json` failures wrap as `CarrelError` with a hint to run `/carrel-setup` to regenerate.
- **Version-consistency test.** `tests/test_version_consistency.py` asserts `pyproject.toml`, `src/carrel/__init__.py`, `.claude-plugin/plugin.json`, and `.claude-plugin/marketplace.json` all report the same version. CI catches drift before deploy.

## Why Now

The April 2026 triangulated review (`planning/reviews/008-deployment-readiness-triangulated.md`) caught Imperial deployment blockers that 0.5.2 would have shipped with: contradictory Windows messaging, Mac-coded /carrel-setup hand-off, procedural coupling on setup-state JSON edits, missing input validation in the hook, no install.ps1 verification step. 0.5.3 closes the deployment readiness gap.

The architectural anchor is the `carrel setup-state` CLI. Multiple bugs across the hook, scaffold, migration docs, and version-source sprawl traced back to the same root cause: state transitions were procedurally coupled (Claude edited JSON directly with no validation boundary). The CLI pulls that boundary into deterministic Python with the Pydantic model as the gatekeeper.

## Automatic Migrations

These run silently with no user action:

1. **Update plugin-state.json**: Version bumped to 0.5.3.
2. **Existing vaults**: no schema changes to `environment.json`. `setup-state.json` consumers (the hook, the new CLI) accept the existing shape; the new mutual-implication invariant is enforced going forward but does not retroactively reject existing files.

## Manual Steps

None required for working vaults. Optional hygiene:

```bash
# Inspect setup-state if you want to verify shape
carrel setup-state show --vault .

# Mark an existing vault as setup-complete (so the hook never offers resume)
carrel setup-state complete --vault .
```

## No Action Required If

- You're a returning user with a working vault — nothing changes for you.
- You don't run on Windows — the cross-platform guidance is additive.
- You don't use the cheat sheet — the renderer changes are additive.
