## Recommendations (PARTIAL + UNIQUE)

### PARTIAL — absorb the orchestration into the skill, drop the command

| Command | Recommendation | Where the unique logic lives now → should live |
|---------|----------------|------------------------------------------------|
| `/carrel-setup` | **(a) Absorb into `environment-setup` skill** + **(c) keep `carrel setup-state` CLI as the durable boundary**. The skill already maps Steps to Phases; move the per-phase `setup-state advance` checkpoints and the conditional handoff branching into the skill body. CLI is already the validation boundary; agent calls it. |
| `/carrel-automate` | **(a) Absorb into `automation` skill**. Move the 10-step flow + trust-check gate + `.prev.md` backup rule + Desktop App walkthrough into the skill. `carrel trust check automation:write-prompt` is already a CLI call — the skill just needs to instruct the agent to run it. |
| `/carrel-batch` | **(a) Absorb into `convert` and `transcribe` skills** (folder-mode) + **(b) new tiny `batch-processing` skill** for the UNATTENDED-mode contract. The headless branch is load-bearing for `automation` and deserves explicit ownership. Alternatively, fold into `automation` skill since that's the only caller of unattended mode. |
| `/carrel-share` | **(a) Absorb into `collaborator-onboarding` skill**. Add the "Quick mode" shortcut, optional canonical copy, and sensitivity-redaction prompt to the existing skill. The skill description already triggers on the right phrases. |

### UNIQUE — needs a home that isn't a Claude-Code-only command

| Command | Recommendation |
|---------|----------------|
| `/carrel-feedback` | **(c) Move to `carrel feedback export --vault .` CLI subcommand**. The anonymization rules are deterministic transforms over `_meta/reflections/` and `_meta/friction_log.md` — exactly what the Python core library should own. Then a thin skill (or no skill) calls the CLI. |
| `/carrel-migrate` | **(c) Move the version-comparison + registry-walk logic to `carrel migrate run --vault .` CLI subcommand**. The `${CLAUDE_PLUGIN_ROOT}` indirection is Claude-Code-specific; the CLI should resolve plugin root explicitly or be invoked with a `--plugin-root` argument. Per-migration markdown files can still exist as documentation the CLI streams back. For non-Claude-Code targets, migrations either ship in carrel core or become CLI-driven advisories. |
| `/carrel-mirror` | **(b) New `research-mirror` skill** capturing the 5-dimension synthesis schema, with `--write` behavior promoted to `carrel vault mirror --write --vault .` CLI subcommand (deterministic file write to `_meta/mirror/YYYY-MM.md`). Skill owns the synthesis prose; CLI owns the file I/O. |
| `/carrel-reflect` | **(b) New `session-reflection` skill** + **(c) `carrel vault reflect log --vault .` CLI** for the file append. The SessionEnd hook is genuinely Claude-Code-only and should remain as a thin trigger that invokes the skill. Other agent harnesses won't have session-end hooks; the skill triggers on natural phrases ("let's wrap up", "reflect on today"). |

### REDUNDANT — safe to drop for non-Claude-Code targets

All 7 are 12-50 line pointers whose triggers and behavior are already in the skill `description` + body. A Codex/Kimi build with skill auto-discovery loses nothing functional by dropping them. (Claude Code users may want them kept as ergonomic shortcuts in muscle memory — that's a UX call, not a functionality call.)

## Verdict (3 paragraphs)

**The hypothesis largely holds, with caveats at the edges.** Of 15 commands, 7 (47%) are pure ergonomic wrappers — they restate a skill's triggers and add no orchestration. Another 4 (27%) are PARTIAL: the *intent* is in a skill, but the command adds discipline — state-tracking checkpoints (`/carrel-setup`), safety gates (`/carrel-automate`'s trust check), idempotency contracts (`/carrel-batch`'s headless mode), or workflow refinements (`/carrel-share`'s quick mode). A capable agent could reconstruct most of these from the skill + the vault's CLAUDE.md, but compliance discipline (e.g., remembering to run `setup-state advance` after each phase) is easy to skip. The remaining 4 (27%) — `/carrel-feedback`, `/carrel-migrate`, `/carrel-mirror`, `/carrel-reflect` — are genuinely UNIQUE: no skill owns the synthesis schema, the migration registry walk, the anonymization transforms, or the session-reflection format. These are real functionality, currently homed only in commands.

**For a Codex/Kimi build, ~73% of commands (REDUNDANT + PARTIAL with light skill absorption) could be safely dropped** if you do two things: (1) merge the PARTIAL commands' orchestration prose into their respective skills, and (2) promote the UNIQUE commands' deterministic logic (anonymization, migration walk, mirror write, reflection append) to `carrel <subcommand>` Python CLI entry points. That leaves the *intellectual* logic (synthesis schemas, reflection prompts) in skills and the *mechanical* logic in the CLI, which matches carrel's stated architecture — "skills = human judgment, core library = deterministic operations, transports = thin." The current command layer is the exception: it mixes both.

**The minimum residue for a non-Claude-Code build is two things, neither of which need to be `/cmd`s:** (a) the Python CLI gains 4 new subcommands — `carrel feedback export`, `carrel migrate run`, `carrel vault mirror`, `carrel vault reflect log` — to absorb the deterministic parts of the UNIQUE commands; (b) the `environment-setup`, `automation`, `collaborator-onboarding`, and (`convert` + `transcribe` + `automation`) skills are extended with the orchestration prose currently in PARTIAL commands, including the explicit CLI calls (`setup-state advance`, `trust check automation:write-prompt`). After that, the only Claude-Code-specific residue is the SessionEnd hook that auto-triggers `/carrel-reflect` — and that's a hook, not a command. For Codex/Kimi, the user simply says "let's wrap up" and the `session-reflection` skill fires. The 15-command surface collapses to ~4 new CLI subcommands and 4 enriched skills, with zero command files needed for cross-harness portability.
